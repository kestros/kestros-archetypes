What's Next

You have been through the whole thing: a framework with nothing in it, libraries, view overrides, versions of both, layouts, variations, core component customisation, components of your own, and services behind them. Nothing on this page was ever edited to make any of that happen - only which framework rendered it.

Best Practices and Tips

  • Lean on the side of modularization. A library that does one thing can be included by every framework that needs it. A framework that does everything can be included by nobody.
  • Strict versioning. Once a version is finalized, it should never change. Changing code in existing versions could have unintended effects if you have multiple sites using a library or framework.
  • Use HTL Templates for markup two views share, rather than copying it. Six identical views teach an author nothing and hide the differences that do exist.
  • Override rather than fork. Step 8's rule holds generally - a view in your codebase beats a core one, and nothing you own has to be re-merged when Kestros moves.
  • Name things for what an author sees. Titles are what appear in the picker, and two nodes sharing a title is a choice nobody can make.

Try it Yourself

Here's some ideas to get you started:

  • Create a UI Library for a popular CSS Framework, and a UI Framework that includes it.
  • Create a Versioned UI Framework, so that you can walk through your development progression.
  • Give one of Kestros's core components a view in your own framework, as step 8 did with the heading above.
  • Add a third layout to your framework and switch a single component onto it.

Clean Up

Delete the tutorial files

The tutorial is ordinary content in your project, so removing it is deleting directories and rebuilding:

  • src/content/jcr_root/apps/${artifactId}/components/tutorial-* - the four tutorial components and every view under them.
  • src/content/jcr_root/etc/ui-frameworks/tutorial-* - the eleven step frameworks.
  • src/content/jcr_root/etc/vendor-libraries/tutorial-* - the three tutorial libraries.
  • src/content/jcr_root/content/sites/${artifactId}-beginner-tutorial and its intermediate and advanced siblings.

Your own ${artifactIdShorthand}-ui and ${artifactIdShorthand}-versioned-ui views are not tutorial files - keep those.

Rebuild a project without the tutorial

Or start again and leave it out: generate from kestros-project-archetype rather than the tutorial archetype, and you get the same project with a single sample component in place of all of the above.
