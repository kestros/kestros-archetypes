Step 8

Customizing core components, from the more-info layout

The core heading above is still wearing this framework's view, because that view belongs to the framework and not to whichever layout of the tutorial component you happen to be reading.

What you can and cannot change

  • You can replace the markup a core component renders, add classes to it, and wrap it in structure of your own.
  • You can give it variations and layouts, the same as any component you wrote.
  • You cannot change what data it reads or what its dialog asks the author for - that is the component's Java model, not its view.

When to reach for it

When a core component is right but does not match your design. Writing a new ComponentType instead means re-implementing its dialog, its validation and its documentation for the sake of markup you could have overridden in one directory.

When the component itself is wrong for what you need, step 9 is the answer instead.
