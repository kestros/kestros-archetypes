Step 8

Customizing Core Component Types

Kestros ships its own ComponentTypes - headings, text, buttons, cards, tables - and a framework can provide views for those exactly as it does for your own. Nothing about the core component changes, and nothing is forked: the view is a directory in your codebase, named after your framework, under the core component's path.

Look at the heading above this component. It is kestros/commons/components/content/heading, and this framework provides a view for it - that is why it does not look the way it did on the earlier steps.

Where it goes

Under src/content/jcr_root/apps/kestros/commons/components/content/heading, in a directory named for the framework code. The core component's own files are never touched, so an upgrade of Kestros cannot conflict with your view.

This is the same precedence rule as step 3, applied one level out: a framework's view beats whatever the component itself provides.
