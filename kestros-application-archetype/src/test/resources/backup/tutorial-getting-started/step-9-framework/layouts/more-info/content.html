Step 9

Creating component types, from the more-info layout

This tutorial component is itself the worked example, and you have been reading its views since step 1. Its own directory is the shape yours will take.

What it contains

  • A .content.xml declaring the ComponentType and its group.
  • A common view, used whenever nothing more specific applies - step 1 was that view.
  • One directory per framework that overrides it, named after that framework's code.
  • An edit directory, holding the dialog authors see in edit mode.

Two components, not one

The panels this tutorial renders beside its steps are separate ComponentTypes - tutorial-framework-view-map and tutorial-step-details - included from the step views with data-sly-resource. Composing small components that way is cheaper than one component with a flag for every arrangement.
