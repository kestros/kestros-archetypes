Step 9

Create New Component Types

Everything so far has been views over components that already existed. A ComponentType of your own is a directory under src/content/jcr_root/apps/${artifactId}/components with a .content.xml declaring it, and at least a common view - which is exactly what the component you are reading is.

What the .content.xml has to say

  • jcr:primaryType of kes:ComponentType, which is what makes it one.
  • A jcr:title, because that is the name authors pick it by.
  • A componentGroup, which is the section of the component picker it appears under. Leave it out and authors cannot find it.
  • A sling:resourceSuperType, usually kestros/commons/components/kestros-parent, which is where edit-mode behaviour comes from.

Then the views

A common view is the fallback and is the only one strictly required. Add framework views beside it as you go, on the same rules you have been using since step 3 - and the documentation and validation pages Kestros generates for the component start working the moment the component exists.
