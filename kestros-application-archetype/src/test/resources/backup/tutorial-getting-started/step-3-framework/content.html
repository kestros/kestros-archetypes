Step 3

Overriding a View

In step 2 the view came from a library. This framework includes that same library, but also declares a view of its own for this ComponentType - and that is the one you are reading. A view on the framework always wins over a view from any library the framework includes.

That is the whole precedence rule, and it is what lets one site override a shared library's markup without forking the library or touching any other site that uses it.

Where This View Lives

In your codebase, at src/content/jcr_root/apps/${artifactId}/components/tutorial-getting-started/step-3-framework. The directory is named after the framework's code, which is how Kestros knows which framework the view belongs to.

The panel beside this one lists every view this ComponentType has, and marks the one being used to render the page right now.
